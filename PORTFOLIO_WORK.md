# Portfolio Website Work Log

## Project

This repository contains the personal portfolio for Kalashree: a multipage site
covering AI, data, backend, frontend, and developer-tool work, plus a writing
system that publishes only what has actually been written.

## Design direction

- Premium editorial visual language: hairline rules, a visible coordinate grid,
  mono labels, and square corners rather than rounded widgets.
- Porcelain Matte default: warm paper canvas with light component surfaces —
  bright, high-contrast, and easy on the eyes (never pure white/black).
- Bold matte cobalt brand, deep teal links, restrained amber highlights,
  espresso ink bands. Four legacy palettes remain available.
- Serif display typography paired with a clean sans-serif interface font.
- Calm professional motion instead of noisy effects: one press language,
  sliding pills, layout-animated filters, draw-in diagrams.
- No particles, custom cursor, neon colors, decorative 3D, or fabricated
  statistics.

## Editorial rule

Every number, date, and claim on this site must be something the author can
defend. Where a real metric does not exist, the content says what was actually
built instead of inventing a figure. Concretely:

- The résumé's "at a glance" figures are counts of things in this repository
  (projects, essays, practice areas, listed tools) — not uptime or latency
  claims, which would need production telemetry.
- Articles have no dates. They are presented as working notes tied to a real
  project, because no publication history exists to cite.
- Planned ideas are labelled as ideas. Nothing is called published until it has
  a body.
- Reading length is shown as a word count rather than a rounded "N min read",
  because these pieces are short and rounding hides the difference.

## Color system

The theme lives in `src/theme.css`, generated by `scripts/generate-theme.mjs`
(`npm run theme`) from seed colors through Material 3 HCT math — never edited
by hand. It is a role-based token system: tonal ramps
(`--md-surface-container-high`, `--md-outline-variant`, `--md-primary`) with the
site's own names bridged onto them (`--canvas`, `--ink`, `--sage`, `--line`).
Components reference roles, never hues, which is why light and dark stay
coherent without a second stylesheet. Every text-bearing pair is checked
against WCAG AA inside the generator, which refuses to write on failure.

Five palettes: Sage Technical, Obsidian Indigo, Terracotta Amber, Nordic Frost,
and the default Porcelain Matte (warm paper, bold cobalt, espresso ink, low
glow mixes for a flat matte finish). The footer is a palette-following
espresso band in every palette; the edition label in the bottom bar names the
active palette.

| Purpose | Light | Dark |
|---|---|---|
| Main canvas | `--md-surface` | `--md-surface` |
| Light card/form surface | `#ffffff` | `#f4f5f1` |
| Signal accent | `--md-primary-container` | `--md-primary` |
| Borders | `--technical-line` | `--technical-line` |

`--signal` and `--signal-strong` are aliases for the primary ramp, so one token
drives buttons, active states, diagram nodes, and progress bars.

## Writing system

### Articles

Four written pieces in `articles` in `src/config.ts`, each carrying block
content. Essays can optionally carry a `projectSlug` when they trace back to a
specific repository:

- Designing a Production API (interactive)
- ETL Pipelines People Can Trust
- Transactional Boundaries That Prevent Drift (StockLedger)
- Diagrams as Data

Block types supported by `ArticleRenderer`: `paragraph`, `heading`, `code`,
`quote`, `table`, `callout`, `diagram`, `interactive`.

### Reading modes

`ArticleToolbar` offers three modes, also bound to the R / E / A keys (ignored
while typing):

- **Read** — the document as written.
- **Explore** — surfaces the interactive models. Only offered when the article
  sets `interactive: true`.
- **Annotate** — enables text selection and opens the workspace panel.

### Annotations

Annotations are semantic anchors, not canvas coordinates: a block id, character
offsets inside that block, and the quoted text as a fallback. They are stored in
`localStorage` under `portfolio-annotations:<slug>` and repainted by splitting
text nodes and wrapping the slice in a `<mark>`.

This is deliberate. Coordinate-based or live-`Range` annotations break on
resize, font loading, and reflow; offsets survive all three and can be restored
on a later visit.

### Diagrams

Diagrams are data, not images — see `diagrams` in `src/config.ts`. A diagram is
nodes with grid coordinates and edges with optional labels; `DiagramRenderer`
computes all pixel geometry and draws inline SVG. That means diagrams inherit
the active theme and stay sharp at any zoom without a second asset.

`diagram-missing` renders an explicit notice if a block references a diagram id
that does not exist, rather than failing silently.

### Interactive models

`ExperimentHost` renders the deterministic model defined in `experiments`. Every
output is computed from the stated assumptions and the arithmetic is shown in a
"How these numbers are produced" panel, so a reader can check the result by
hand. Hit ratios are declared constants (edge 0.72, Redis 0.86) rather than
implied telemetry.

## Résumé canvas

Clicking **Résumé** in the header opens a full-screen canvas with a dark toolbar
and a light paper surface: profile, at-a-glance counts, practice areas, selected
work with repository links, skills, and working principles.

- Escape closes it; the backdrop closes it; focus moves into the dialog and page
  scrolling is locked while it is open.
- **Print** prints the document without site chrome.
- **Download PDF** serves `public/resume.pdf`, which is generated from the same
  component (see below).

## Generating the résumé PDF

```powershell
npm run resume:pdf
```

This builds a single-page bundle of `ResumePaper` (the same component the canvas
renders), prints it with installed Edge or Chrome in headless mode, and writes
`public/resume.pdf`. Editing `resumeData` and re-running the command refreshes
the downloadable document, so the PDF and the on-screen résumé cannot drift
apart.

`vite.resume.config.ts` and `scripts/resume-print/` exist only for this build.
The `--allow-file-access-from-files` flag in the script is required: without it
Chromium blocks the ES modules over `file://` and prints a blank page.

If no browser is found, the script says so and suggests opening `/print/resume`
in the dev server and printing manually.

## Motion system

One language, two libraries, divided by job:

- **motion.dev** owns entrances, exits, and layout: `Reveal` scroll reveals,
  hero stagger, sliding `Pill` indicators (nav underline, mode tabs, all
  filter rows, contact topics), `ListItem` layout-animated filter results,
  `Expand`/`Pop` menus and dropdowns, exit choreography for the résumé
  canvas and annotation workspace, spring-smoothed progress bars, and
  draw-in SVG diagrams. Tokens live in `src/lib/motion.ts`, mirroring the
  CSS motion tokens.
- **GSAP ScrollTrigger** owns scroll-linked moments only: hero and feature
  parallax (`data-gsap="parallax"`) and the home signal-strip count-up to
  real figures (`src/hooks/useGsapSite.ts`).
- A CSS micro-layer (`MICRO-INTERACTIONS` in `src/index.css`) gives every
  control the same press-down settle and live-token pills.
- `prefers-reduced-motion` disables all of it: pills render static,
  presences fade instantly, parallax and count-ups skip.

## Tooling notes

- `npm run build` runs `tsc -b` then `vite build`.
- `npm run lint` runs ESLint. Two `react-hooks/set-state-in-effect` findings are
  suppressed with an explanatory comment and a `eslint-disable-next-line`:
  Embla has no state until mounted, and the header must read the real scroll
  position once on mount. Both are genuine synchronisation-with-an-external-
  system cases.
- The dev server binds IPv6 only, so use `http://localhost:3000/` rather than
  `http://127.0.0.1:3000/`.
